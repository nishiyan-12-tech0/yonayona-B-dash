# 29　ミチスジ　利用ガイド v0.2（たたき台）

2026年11月16日 ｜ 対象の画面：[モック v7](ミチスジ_モック_v7_20261116.html) ｜ 前の版：[v0.1](旧版/29_ミチスジ_利用ガイド_v0.1_20261116.md) ｜ 項目の決めごと：[設計書25 v0.4](25_ミチスジ_戦略マップ・申請書_設計書_v0.4_20261115.md)

> このガイドは、画面ごとに「見る人・入力する人」の目線で、何を書くか、どう読むかを説明するもの。
> 書いていて説明できなかった所には **【要確認】** を付け、最後の6章に一覧にした。次に直す所の候補として使う。

このガイドの前提（11/16に決めたこと）
- 申請の項目は、すべて必須で入力する前提。戦略マップで使わない項目は入力させない
- 企業情報は入力させない（経産省側でGビズIDと連携して取得する想定）
- 過去の申請内容（DX認定・DX調査など）の取り込みはしない。描くのはこれからの戦略
- 戦略マップの「今回確認・判断したいこと」の一覧と、申請ステップ8の「未決のこと」の一覧はなくした
- 画面の名前は「申請」（v0.1では「申請書」）

## 0. 全体の流れ

| 順 | 場面 | 人 | 画面 | すること |
|---|---|---|---|---|
| 1 | 事業計画を立てる | 経営層、事業部の責任者 | ① 申請　ステップ0〜3（第1層） | 事業の財務目標、顧客への価値、変える業務を決める |
| 2 | DXをどこに入れるか決める | 上の2者＋DX推進部（入力はDX推進部） | ① 申請　ステップ4〜6（第2層） | 決めた目標に至る方法として、必要な力と施策を付ける |
| 3 | 読み合わせて登録する | 全員 | ① 申請　ステップ7〜8 | 一枚で確認し、戦略マップを表示する |
| 4 | 担当者に共有する | 事業部・DX推進部の担当者 | ② 戦略マップ | 自分の仕事が、事業の目標のどこにつながるかを読む |
| 5 | 自社の位置を見る | 事業部・DX推進部の責任者、経営層 | ③ 他社と比べる | 同じ業種の事業と比べて、自社の事業がどこにいるかを見る |
| 6 | 全体を見る | 経産省の担当者 | ④ 経産省の画面 | 参加企業の事業の分布を見る |
| 7 | 半年〜1年ごとに更新する | 事業部、DX推進部 | **【要確認】** | 指標の今の値、施策の状態を更新する |

## 1. 申請　第1層（経営層・事業部の責任者向け）

**ここで決めるのは「事業としてどこを目指すか」だけ。** システムやDXの話は、まだ書かない。第1層が終わると、戦略マップの右側3列（変える業務・顧客に起きる変化・売上・利益への貢献）ができる。

画面の上にある「入力中の事業」で、事業を切り替えながら入力する。ステップ1〜6は事業ごとに入力する。

### ステップ0　会社と事業

| 項目 | 何を書くか | 記入例（架空企業） |
|---|---|---|
| 全社の財務目標 | 目標、指標、基準、今、目標、期限 | 連結の営業利益を伸ばす／連結営業利益／180億円／190億円／260億円／2028年度 |
| 対象にする事業 | 事業名、業種、全社売上に占める割合、責任者 | 産業機器事業／はん用・生産用機械／70%／産業機器事業部長 |

- 企業名や業種などの企業情報は入力しない
- **考える観点**：事業は「責任者が1人いて、顧客と財務目標を別に持っている単位」で切る
- **迷いやすい点**：売上がまだない新規事業は0%にする

**【要確認】** 全部の事業を出すのか、DXに関係する事業だけでよいのかが決まっていない。
**【要確認】** モックに事業を追加・削除する操作がない。

### ステップ1　財務の目標

| 項目 | 何を書くか | 記入例 |
|---|---|---|
| 今との差 | 中期経営計画の目標と、今の差 | ＋150億円（2028年度） |
| 差の埋め方 | 差のうち、売上を増やして埋める分（収益増大）と、コストを下げて埋める分（生産性向上）の割合 | 収益増大70%／生産性向上30% |
| 財務の目標 | 目標、種類（収益増大／生産性向上）、指標、基準、今、目標、期限 | 既存顧客からの売上を伸ばす／収益増大／既存顧客からの売上／1,200億円／1,240億円／1,350億円／2028年度 |

- **考える観点**：中期経営計画の数字をそのまま使う。効率化だけで差を埋める計画になっていないかを、ここで確かめる
- **迷いやすい点**：「基準」は計画を立てた時点の値。あとの更新で上書きしない。「今」だけを更新していく

**【要確認】** 「差の埋め方」の割合を、何の金額をもとに出すのか（売上の差か、利益の差か）が画面に書かれていない。

### ステップ2　顧客への価値

| 項目 | 何を書くか | 記入例 |
|---|---|---|
| 対象の顧客 | この事業が価値を届ける相手 | 当社設備を使う工場の保全部門・生産技術部門 |
| 顧客価値提案の類型 | 4つから1つ選ぶ（下の表） | 完全な顧客ソリューション |
| 将来の提供価値 | 目標の年に、顧客に何を提供できているか | 顧客の設備を止めず、段取りも短くできる機械と保守を提供している |
| 顧客の成果目標 | 目標、指標、基準、今、目標、期限 | 保守契約を続けてもらう／保守契約の継続率／82%／84%／90%／2027年度 |

類型の選び方（類型は Kaplan & Norton『戦略マップ』のもの。設計書25 v0.4 の2-1を参照。右の言い換えはこのガイドで付けた説明で、原典では確かめていない）

| 類型 | ひとことで言うと |
|---|---|
| トータル・コスト・リーダーシップ | 安さ、手間の少なさで選ばれる |
| 製品リーダーシップ | 製品の性能や新しさで選ばれる |
| 完全な顧客ソリューション | 顧客ごとの困りごとを、まとめて解決することで選ばれる |
| システムロックイン | 自社の仕組みが標準になり、乗り換えにくいことで選ばれる |

- **考える観点**：「将来の提供価値」は技術の名前を使わずに書く（×AIの導入　○設備を止めない保守）
- **迷いやすい点**：類型は1つだけ選ぶ。全部を少しずつ、は選べない

**【要確認】** 対象の顧客と将来の提供価値は、事業に1つずつしか書けない。テーマごとに顧客や目指す姿が違う事業では、書き分けられない。

### ステップ3　戦略テーマと業務

| 項目 | 何を書くか | 記入例 |
|---|---|---|
| 戦略テーマ（1〜3個） | テーマ名、取り組む期間の目安（短期0〜1年／中期1〜3年／長期3〜4年） | 保守を「壊れてから」から「止めない」へ／中期（1〜3年） |
| 変える業務 | 目標、テーマ、主担当、協働、指標、基準、今、目標、期限 | 稼働状況に応じて保守を提案する／（上のテーマ）／事業部／DX推進部／稼働データを使った提案件数／月20件／月42件／月60件／2027年度 |
| 事業側で確認した人・日付 | 第1層の内容を確認した責任者と日付 | 産業機器事業部長／2026-04-15 |

- **考える観点**：テーマ名は「何を、何に変えるのか」が分かる言い方にする。戦略マップで、担当者が最初に読む言葉になる
- **迷いやすい点**：「変える業務」は、やること（施策）ではなく、変わったあとの業務の姿で書く

**【要確認】** 主担当の選択肢が「事業部／DX推進部」の2つしかない。部署名や担当者名は入れられない。
**【要確認】** 指標を必須にすると、「保守メニューを予防型に組み直す」のような、やり遂げること自体が目標の業務には指標を置きにくい（架空企業のデータでも、ここは指標が空欄になっている）。
**【要確認】** モックにテーマ・目標を追加・削除する操作がない。

## 2. 申請　第2層（DX推進部向け。事業部と一緒に決める）

**第1層で決まった目標は変えない。** ここで足すのは、その目標に至るための方法（必要な力と施策）。入力するのはDX推進部だが、中身は事業部と話して決める。第2層が終わると、戦略マップの左端の列（必要な人・データ・体制）と、施策、矢印ができる。

### ステップ4　必要な力と施策

**必要な力（学習と成長の目標）**

| 項目 | 何を書くか | 記入例 |
|---|---|---|
| 目標 | 「変える業務」を実現するために、今足りていないもの。整ったあとの状態で書く | 必要な稼働データがそろっている |
| 資本の種類 | 情報資本（データ・システム）／人的資本（スキル・人数）／組織資本（文化・協働の仕組み） | 情報資本 |
| テーマ、主担当 | どのテーマのためのものか、どちらの部門が主に担うか | 保守を「壊れてから」から「止めない」へ／DX推進部 |
| 指標、基準、今、目標、期限 | 整い具合を測る指標 | 必要データの欠損なし率／70%／91%／98%／2027年3月 |

**施策**

| 項目 | 何を書くか | 記入例 |
|---|---|---|
| 施策 | 実際にやること | 稼働データの連携基盤 |
| 付ける目標（この事業） | その施策が、どの目標のためのものか | 必要な稼働データがそろっている |
| 主担当 | 事業部／DX推進部 | DX推進部 |
| デジタル、IPA項目 | デジタルの施策なら、下の7つから1つ選ぶ | 3. 既存製品・サービスの高付加価値化 |
| 実行、検証 | 検討中・試行中・実行中・中止／未測定・確認中・効果あり・効果なし | 実行中／確認中 |

IPA項目の選び方：**その施策が何を変えるか**で選ぶ。段階は選んだ項目から自動で表示される（分類の出典：IPA『DX動向2025』本文 p.16 図表1-19。設計書25 v0.4 の2-2を参照）

| 項目 | 段階 | 架空企業での例 |
|---|---|---|
| 1. アナログ・物理データのデジタル化 | デジタイゼーション | — |
| 2. 業務の効率化による生産性の向上 | デジタライゼーション | 組立実績の自動収集 |
| 3. 既存製品・サービスの高付加価値化 | デジタライゼーション | 稼働データの連携基盤 |
| 4. 新規製品・サービスの創出 | DX | 検査データのAI解析PoC、故障予知モデルのPoC |
| 5. 組織横断／全体の業務・製造プロセスのデジタル化 | DX | 全社データ基盤 |
| 6. 顧客起点の価値創出によるビジネスモデルの根本的な変革 | DX | 予防保守の顧客ポータル |
| 7. 企業文化や組織マインドの根本的な変革 | DX | データ解析の研修 |

- **考える観点**：目標は「状態」、施策は「やること」。「データ基盤を導入する」は施策で、目標は「必要なデータがそろっている」
- **迷いやすい点**：利用率や導入数は、施策の指標（準備がどれだけ整ったか）。事業の成果は、右側の目標の指標で見る

**【要確認】** すでに進めている施策で、どの事業の目標にも付かないもの（架空企業では「社内チャットAI」）の扱い。すべて必須にするなら、「付けない」のまま登録できるのか、登録させないのかを決める必要がある。
**【要確認】** 1つの施策が複数のIPA項目にあたる場合に、どれを選ぶかの決まりがない。
**【要確認】** 複数の事業に付く施策（全社データ基盤）を、どの事業の入力画面で、誰が登録するのかが説明できない。画面では事業ごとに「付ける目標」を1つ選ぶ形になっている。
**【要確認】** モックに目標・施策を追加・削除する操作がない。

### ステップ5　つながりと検証

| 項目 | 何を書くか | 記入例 |
|---|---|---|
| 元の目標 → 先の目標 | どの目標が、どの目標につながるか | 必要な稼働データがそろっている → 稼働状況に応じて保守を提案する |
| 理由（仮説） | 元の目標が進むと、なぜ先の目標が進むのか | 欠損のない稼働データがあれば、故障の前に提案できる |
| 成り立つ条件 | その理由が成り立つための前提 | 提案に使える精度のデータが取れる |

- **考える観点**：つながりは「こうなるはず」という仮説。「AができるとBが起きる。なぜなら〜」を1文で書く
- **迷いやすい点**：矢印は目標から目標へ引く。施策からは引かない

**【要確認】** 入力の量。産業機器事業だけでつながりが7本あり、それぞれ4項目を書く。すべて必須にしたとき、誰が何時間かけるのかを説明できない。
**【要確認】** 「変える業務 → 顧客 → 財務」のつながりは事業部が決める内容だが、画面では第2層（DX推進部が加わったあと）に入っている。

### ステップ7　道筋にあるDX（入力なし）

入力はない。ステップ4で選んだIPA項目ごとに、「その施策から、道筋がどこまで進んだか」が表で出る。

- **道筋の進みとは**：試行・実行中の施策が付いた目標から右へたどり、指標が基準値より良くなった目標を順につないで、届いた一番右の列（設計書25 v0.4 の6章）

## 3. 戦略マップ（事業部・DX推進部の担当者向け）

**この画面は、自分の仕事が、事業の目標のどこにつながっているかを見るためのもの。** 入力はしない。

### 読む順番

1. **一番上のテーマ名**を読む。事業が「何を、何に変えようとしているか」が書いてある。テーマ名の上に、取り組む期間の目安が出ている
2. その下の**対象の顧客**と**実現したい変化**を読む。誰のために、どうなりたいのか
3. 右の**主要な成果指標**を見る。今の値と、目指す値、期限
4. 下の4つの列を、**左から右へ**読む。「必要な人・データ・体制」が整うと →「変える業務」ができ →「顧客に起きる変化」が生まれ →「売上・利益への貢献」になる
5. 箱の右上の「主担当」、施策の「担当」で、**自分の部門の箱と施策**を探す

### 画面の部分ごとの意味

| 部分 | 意味 |
|---|---|
| 上の事業名のボタン | 見る事業を切り替える |
| 「テーマごと／全体マップ」 | 1つのテーマだけを見るか、全部の事業・テーマを並べて見るか |
| テーマ名の下の丸いボタン | 同じ事業の、ほかのテーマに切り替える |
| 「目標」の箱 | 目指す状態。上から、目指す状態、指標の名前、今の値／目標の値、期限 |
| 「指標：改善／横ばい／悪化」 | 指標の今の値が、計画を立てたときの値（基準値）と比べてどう動いたか |
| 「実施する施策」 | その目標のために、実際にやっていること。担当、実行の状態、効果の検証の状態が付く |
| 「効果の検証：確認中」など | その施策が効いたかどうかを、確かめたかどうか |
| 「複数の事業で共通」 | ほかの事業の目標にも付いている施策 |
| 矢印 | 「左の目標が進むと、右の目標が進むはず」という仮説 |
| 箱や施策を押すと出る右の欄 | 詳しい中身。基準値、手前と先の目標、つながりの理由、次に確かめること |
| 「表示オプション」 | 過去の時点を見る、担当やDXの段階で強調する、IPAの項目番号を出す |

### 聞かれそうな質問

- **自分がやっている施策はどこにある？**　→「実施する施策」の中から名前で探す。見つからなければ「全体マップ」に切り替える
- **「指標：改善」は、施策がうまくいったということ？**　→ ちがう。指標が良くなった、という事実だけ。施策が効いたかどうかは「効果の検証」で別に見る
- **矢印は決まったこと？**　→ 仮説。矢印の元の箱を押すと、理由と、いつ何で確かめるかが出る
- **全体マップとのちがいは？**　→ 全体マップは、全部の事業とテーマを同じ形で並べたもの。会社全体の中で、今のテーマがどこにあるかが分かる

**【要確認】** 担当者が「自分の箱」を探す手がかりが、事業部／DX推進部／経営の3つの区分しかない。部署名や担当者名では探せない。
**【要確認】** ストーリーとして読める文章がない。箱と矢印を自分でつないで読む必要があり、つながりの理由は、箱を押して詳細を開かないと見えない。「なぜやるのかを知らない担当者が、全体のストーリーを理解する」という目的に対して、一番弱い所。
**【要確認】** 「実現したい変化」は事業に1つで、テーマごとの言葉ではない。テーマを切り替えても同じ文が出る。
**【要確認】** 最初に見えるのは1つのテーマだけ。事業全体や会社全体のストーリーは、「全体マップ」に切り替えないと見えない。
**【要確認】** 「指標：未設定」の箱や点線の箱など、すべて必須にするなら出ないはずの表示が残っている。架空企業のデータにも空欄がある。
**【要確認】** 箱の数字（今の値）を、誰がいつ更新するのかを説明できない（0章の7と同じ）。
**【要確認】** 担当者は見るだけでよいのか、何か書き込める所が必要なのかが決まっていない。

## 4. 他社と比べる（事業部・DX推進部の責任者、経営層向け）

**この画面は、自社の事業が、ほかの会社の事業と比べてどこにいるかを見るためのもの。** 他社の名前や順位は出ない。

### 画面の部分ごとの意味

| 部分 | 意味 |
|---|---|
| 「比べる相手」 | 同じ業種の事業だけと比べるか、参加企業の全事業と比べるか |
| マス目の**横** | 道筋の進み。左から、まだ動いていない／学習と成長／業務プロセス／顧客／財務。施策から順に、指標が良くなった所まで |
| マス目の**縦** | その事業で試行・実行中のデジタル施策のうち、一番上の段階（デジタイゼーション／デジタライゼーション／DX） |
| 色の付いた点 | 自社の事業。1つの事業が1つの点 |
| 白抜きの点と点線 | 前回（2026年3月末）の位置と、そこからの動き |
| マスの濃さと数字 | 比べる相手の事業のうち、そのマスにいる割合 |
| 「自社の事業」 | 事業ごとに、道筋にあるDXの段階と項目、道筋の進み（前回 → 現在） |
| 「項目ごとの比較」 | 自社と、比べる相手の平均。財務の目標までつながっている目標の割合／実行条件の確保がある施策の割合／検証と次の判断日が決まっている施策の割合／検証が済んだ施策の割合／指標がどの列に置かれているかの構成 |
| 「道筋にあるDX（IPAの7項目）」 | 事業 × 項目の表。その項目の施策から、道筋がどこまで進んだか。「—」はその項目の施策がない |

### 読み方

- **右にいるほど**、施策から始まった変化が、顧客や財務の指標まで届いている
- **上にいること自体は評価しない。** 段階が高くても、左にとどまっていれば、道筋は進んでいない
- 前回の白抜きの点から右へ動いていれば、この半年〜1年で進んだことになる

### 聞かれそうな質問

- **順位は出ないのか？**　→ 出さない。施策や事業の切り方が会社ごとに違うため
- **他社の名前は見えるのか？**　→ 見えない。割合だけ
- **マス目に出ていない事業があるのはなぜ？**　→ 試行・実行中のデジタル施策がない事業は、マス目には出ない（一覧には出る）

**【要確認】** 架空企業は3つの事業すべてが「DX」の行に入る。縦の差が出ず、横の位置しか比べられない（設計書25 v0.4 の未決事項1と同じ）。
**【要確認】** 戦略マップ（v7）では「道筋の進み」を表から外し、詳細の奥に入れた。責任者がこの画面で「財務まで進んだ」と見ても、戦略マップのどこを見ればそれが分かるのかを説明できない。2つの画面で言葉と見せ方がつながっていない。
**【要確認】** 比べたあとに、責任者が何をするのかを書けない。「同じ業種より左にいる」と分かったあとの行動が、画面にも設計にもない。
**【要確認】** 「項目ごとの比較」の4つの割合は、すべて必須にするなら自社はほぼ100%になるものがある（実行条件の確保、検証と次の判断日）。比べる意味が残るかを確かめる必要がある。

## 5. 経産省の画面（経産省の担当者向け）

**この画面は、参加している企業の事業が、全体としてどこにいるかを見るためのもの。**

### 画面の部分ごとの意味

| 部分 | 意味 |
|---|---|
| 上の5つの数字 | 参加企業数（事業数）／直近1年以内に更新した企業数／顧客・財務まで道筋が進んだ事業の割合／業務プロセスで止まっている事業の割合／どの目標にも付いていない施策の割合 |
| マス目 | 参加企業の全事業の分布。横と縦の意味は「他社と比べる」と同じ。数字は、全事業のうちそのマスにいる割合 |
| 業種別の棒 | 業種ごとの、顧客・財務まで道筋が進んだ事業の割合 |
| 「指標はどの視点に置かれているか」 | 指標が、学習と成長／業務プロセス／顧客／財務のどこに何割あるか。全体と業種別 |
| 企業一覧 | 企業名、業種、対象の事業数、道筋が一番進んだ事業（段階・進み）、最終更新 |

### 読み方

- マス目で、「段階は高いが、道筋が左で止まっている事業」がどれだけあるかを見る
- 「指標はどの視点に置かれているか」で、指標が社内の効率化（学習と成長・業務プロセス）に偏っていないかを見る。参考として画面に出している数字：成果指標の対象は「内向きの業務改革（社内の効率化）」が80.0%、「外向きの業務改革（新たなビジネスや顧客価値の創出）」が33.5%（IPA『DX動向2026』p.19 図表2-15、複数回答。手元：参考資料/dx-trend-2026.pdf）

**【要確認】** 企業一覧から、その企業の戦略マップを開けるのかどうかが決まっていない。モックでは開けない。
**【要確認】** 「どの目標にも付いていない施策の割合」は、すべて必須にして、付いていない施策を登録させないなら、0%になる（2章ステップ4の要確認と同じ）。
**【要確認】** 更新が止まっている企業をどう扱うか（一覧に残すか、集計から外すか）が決まっていない。
**【要確認】** 本番では経産省が確認してから反映する想定だが、確認のための画面がない（発表用モックの範囲外。設計書25 v0.4 の10章）。
