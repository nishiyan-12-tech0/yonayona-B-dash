## 1. ミチスジとは

**事業部・経営・DX推進部が、「事業の目標に向かう道筋」を1枚の戦略マップに描き、そこにDXの施策を位置づけるためのWebサービス。** 経産省が提供し、半年〜1年ごとに更新してもらう。

- 起点は**事業の目標**（売上・利益と、それを生む顧客への価値）。DXの施策は、その目標に付ける「手段」として描く
- 描いたマップから、**目標につながっていない施策**と、**施策がない目標**が自動で見つかる
- DXの段階（IPAの3段階・7項目）はマップの中に埋め込む。見るのは「段階に着いたか」ではなく、**その段階の施策から、道筋がどこまで進んだか**
- 匿名の他社（同じ業種の事業）と比べて、自社の事業が道筋のどこにいるかが分かる
- 経産省は全体の分布を見て、評価・表彰の基準を道筋の上で示すのに使う

名前の由来：今やっていることから事業の目標までの「道筋（ミチスジ）」を描く、という意味。ロゴの道しるべは、目指す先（右向きの看板）と、ここまで来た道（左向きの矢印）を表す。

## 2. なぜ作るのか

### 2-1 日本企業のDXの成果指標は「社内の効率化」に偏っている

- DXの成果指標を設定している企業に指標の対象を聞くと、「内向きの業務改革（社内の効率化）」が80.0%と最も高い。「外向きの業務改革（新たなビジネスや顧客価値の創出）」は33.5%、「経営改革（デジタル事業売上高、市場シェア等）」は16.3%にとどまる（IPA『DX動向2026』p.19 図表2-15。手元：参考資料/dx-trend-2026.pdf）
- DX認定では、「DX戦略に定められた計画の進捗を評価する指標」（例：データ活用基盤の社内部門別導入数、顧客向けアプリ利用者数）が公表されていれば、指標の要件を満たせる（IPA『DX認定 申請ガイダンス』p.28。手元：参考資料/国内外ツールとDX認定_深掘り_20261028/DX認定_申請ガイダンス.pdf）

### 2-2 チームの見立て

ここからはチームの仮説（ヒアリングと調査メモ31のイシューツリーから）。

- DX推進部はITに強いが、事業の現場に詳しくない。そのため指標が利用率・導入率・削減時間に偏りやすい
- DX推進部の指標は、事業部の協力なしには達成できない。それなのに、事業部と目標を合わせる場がない
- **事業の成果を決める場にDXの道筋を持ち込めば、目標が重なり、現場が動きやすくなる**（11/14にチームで決めた解決仮説。実証済みではない）

### 2-3 国がやる理由

- 経産省は企業の失敗に責任を持てないので、「このKPIで、この評価制度を」とは言えない。言えるのは「自社で決めた目標に施策と役割をつなげてみて」まで（11/11 経産省ヒアリング）
- だからミチスジは**答えを出さず、描く枠組みと、比べるための道筋を出す**。企業が自分で決めた目標に、自分で道筋を引く
- 国として1つの道筋を示し、その上に他社のデータを集め、評価・表彰の基準を置くことは、民間のツール単体ではできない

### 2-4 評価・表彰とのつながり（チームの考えと提言）

ここは事実ではなく、チームの考え。

- お金のインセンティブは出さない。経産省がこの道筋に沿って評価・表彰する
- 今のDX銘柄は、個々の取組を点で評価しているため、何が基準なのかが企業から見えにくい、というのがチームの見立て（裏づけの事実は未整理）
- 国として「DXとはこういう道筋だ」を示し、「どの段階の施策で、道筋のどこまで進んだか」を基準にできれば、評価の意味が企業にも投資家にも伝わりやすくなる、と考えている
- 提言：DX銘柄などの表彰の基準を、この道筋の上で示す形に見直す。どう見直すかは経産省が決めること

## 3. 誰が、いつ、どう使うか

作る順番：**まず事業部と経営が事業の目標を決める。そのあとDX推進部が加わり、三者で「どこにDXを使うか」を決める。**

| 人 | いつ | 何をするか |
|---|---|---|
| 事業部（事業の責任者・企画）と経営 | 中期経営計画・年度計画のとき | 事業の財務目標、顧客への価値、変える業務を決める（申請書の第1層） |
| DX推進部のプロジェクト責任者 | そのあと、同じ場に加わる | 必要な力（データ・人・組織）と施策を、事業部の目標に付ける。実行の準備（予算・工数、検証の時期）を事業部と確かめる（第2層） |
| 経営層 | 報告を受けるとき | マップを見て、目標と施策がつながっているか、足りないところはどこかを確認する |
| 経産省 | 年1回の集計 | 参加企業の事業が、道筋のどこにいるかの分布を見る。評価・表彰の基準に使う |

利用シーンの例（モック v4の架空企業と同じ）：
1. 産業機器メーカーの産業機器事業部と経営が、来年度の計画を話し合う
2. 申請書に沿って、先に「保守契約の継続率を上げ、既存顧客からの売上を伸ばす」という事業の目標を決める
3. そこにDX推進部が加わり、「稼働データの連携基盤」をどの目標に付けるかを決める
4. マップを見ると、DX推進部が進めている「社内チャットAI」がどの目標にも付いていないことが分かる
5. 次の更新までに、つなげるか、やめるかを決める

## 5. 使っている考え方

### 5-1 骨格：バランスト・スコアカード（BSC）の戦略マップ

- BSCは、財務・顧客・業務プロセス・学習と成長の4つの視点で戦略を表す。戦略マップは、その目標どうしの因果を1枚に描いたもの（Kaplan & Norton「Having Trouble with Your Strategy? Then Map It」HBR 2000年9–10月号 → [原文PDF](https://fenix.iseg.ulisboa.pt/downloadFile/281608120752633/Kaplan%20Norton%20(2000).pdf)）
- 学習と成長が最も先行し、財務が最も遅行する。学習と成長は、人的資本（スキル・知識）、情報資本（データベース・情報システム・技術インフラ）、組織資本（文化・リーダーシップ・チームワーク）からなる（Kaplan & Norton『戦略マップ』2004。[noteの要約](https://note.com/zum_ism/n/nf9895177fd81)で確認、原典は未確認）
- 戦略マップは「因果の仮説の集まり」で、作ったあとに筋が通るかを確かめ続けるもの（同上）
- **ミチスジでの使い方**：4つの視点を左（先行）から右（遅行）に並べて列にした。元の図は下から上だが、「今やっていることが、先のどこにつながるか」を読みやすくするために寝かせた

### 5-2 DXの施策は「学習と成長」の準備として描く

- 『戦略マップ』では、情報資本を基幹業務・分析・変革のアプリケーションと技術インフラに分け、戦略テーマごとに開発状況・安定稼働・利用率で評価する（同上）
- **ミチスジでの使い方**：DXの施策は、主に学習と成長（情報資本）の目標に付くチップとして描く。**利用率や導入率は悪い指標ではなく、「準備がどれだけ整ったか」の指標**として位置づける。それだけでは事業の成果にならないので、右側の業務・顧客・財務までつながっているかをマップで確かめる
- 施策を左端の列にしなかったのは、**DXを起点にしないため**。DXは手段で、起点は事業の目標

### 5-3 財務の2本柱と、顧客価値提案の四類型

- 財務は「収益増大」と「生産性向上」の2本柱で組み立てる。目標と現状の差を、収益増大分と生産性向上分に分けて示す（同上）
- 顧客価値提案は、トータル・コスト・リーダーシップ／製品リーダーシップ／完全な顧客ソリューション／システムロックインの四類型から1つを選ぶ。「すべてを少しずつ」は戦略にならない（同上）
- **ミチスジでの使い方**：申請書の最初に、事業ごとの財務の差と2本柱の内訳、顧客価値提案の類型を聞く。生産性向上（効率化）だけで差を埋める計画なのか、収益増大も描けているのかが、最初に見える

### 5-4 戦略テーマと時間軸

- 業務プロセスは、業務管理・顧客管理・イノベーション・規制と社会の4つに分かれる（同上）
- 成果が出るまでの時間の目安は、業務管理が短期（0〜1年）、顧客管理が中期（1〜3年）、製品開発力などが長期（3〜4年）（同上）
- **ミチスジでの使い方**：事業ごとに戦略テーマを1〜3個まで描く。テーマには業務プロセスの分類と時間軸を付ける。短期のテーマばかりでないかが一目で分かる

### 5-5 複数の事業がある会社：全社 → 事業部 → 支援部門

- 『Alignment』（2006）は、全社の優先事項を事業部の戦略へ、事業部の優先事項を支援部門の戦略へ反映する流れを示している（[HBS Working Knowledge の著者抜粋](https://www.library.hbs.edu/working-knowledge/managing-alignment-as-a-process)）
- 事業部の指標は、全社の指標に影響するものを選べばよく、同じである必要はない（[HBS Working Knowledge「Partnering and the Balanced Scorecard」](https://www.library.hbs.edu/working-knowledge/partnering-and-the-balanced-scorecard)）
- **ミチスジでの使い方**：マップは1枚で、帯を全社と事業ごとに分ける。DX推進部は支援部門として、事業の目標に施策を付ける。1つの施策（全社の基盤など）が複数の事業に付いてもよい

### 5-6 DXの段階：IPAの3段階・7項目を、道筋の中に埋め込む

- IPAは、DXレポート2の3段階（デジタイゼーション／デジタライゼーション／デジタルトランスフォーメーション）を、7つの取組項目に分けている（分類の対応を確認した出典：[IPA『DX動向2025』本文 p.16 図表1-19](https://www.ipa.go.jp/digital/chousa/dx-trend/tbl5kb0000001mn2-att/dx-trend-2025.pdf)）
- **ミチスジでの使い方**（チームの設計案）：
  - デジタルの施策に、7項目のどれにあたるかのタグを企業が選んで付ける。段階はタグから自動で決まる（1＝デジタイゼーション、2・3＝デジタライゼーション、4〜7＝DX）
  - **「自動」とは**、選ばれたIPA項目を対応表に従って段階表示に変換すること。例えば、項目3「既存製品・サービスの高付加価値化」を選ぶと「デジタライゼーション」と表示する。施策の文章をAIなどが読み取って分類する機能ではない
  - **段階と道筋の進みは別**。段階は企業が選んだIPA項目から、道筋の進みは入力された指標の変化から出す。指標が改善したことで、項目3の施策がDXに分類し直されるわけではない
  - 「未着手／取り組み中／成果が出ている」を企業に申告させない。その項目の施策から、道筋がどこまで進んだかを、指標の動きから出す
  - 戦略マップで「DXの段階で見る」を選ぶと、その段階の施策と、そこから財務までの道筋が強調される
- **考え方**：1つの施策だけでDXになるわけではない。事業の目標に向かう道筋の中に、どの段階の施策が入っていて、その道筋がどこまで進んだかを見る。段階に着いたこと自体は評価しない。本当のゴールは右端の財務（成長）

### 5-7 道筋の進み（チーム独自）

- 試行・実行中の施策が付いた目標から始めて、矢印を左から右へたどる。指標が基準値から目標の方向へ動いた目標を順につなぎ、届いた一番右の視点を、その事業の進みとする
- **途中の目標が動いていなければ、その先は数えない。** 見るのは「施策を実行した道筋の上で、指標がどう動いたか」。道筋の外で売上だけが伸びても、進みには数えない
- 例（モックの架空企業）：産業機器事業は、2026年3月末は「学習と成長まで」。その後、提案件数 → 継続率 → 既存顧客の売上と順に動き、現在は「財務まで」

### 5-8 実行の準備（チーム独自）

施策ごとに、次の2つが決まっているかを確かめる。
1. **実行条件の確保**：予算・工数・権限・データの提供者が決まっている。予算は、『戦略マップ』の「戦略投資は通常の予算と別枠で確保する（STRATEX）」という考え方を参考にする（[noteの要約](https://note.com/zum_ism/n/nf9895177fd81)）
2. **検証と次の判断日**：何をいつ確かめ、続ける・直す・やめるをいつ決めるか

事業部とDX推進部の「目標と役割の合意」は、別には聞かない。事業部と経営が先に決めた目標にDX推進部が加わって作るので、申請書を出した時点で合意は済んでいるため（v0.3までの組込みチェック①をなくした理由）。

評価・報酬の変更は条件にしない。BSCの導入企業でも、スコアカードを報酬と連動させるのは約1年運用して指標を確かめてからのことが多いと報告されている（Kaplan & Norton, Accounting Horizons 15(2), 2001, pp.151–152 → [PDF](https://mycourses.aalto.fi/pluginfile.php/2117268/mod_page/content/5/Transforming%20the%20Balanced%20Scorecard%20from%20Performance%20Measurement%20to%20Strategic%20Management-%20Part%20II.pdf)）。※これは連動の時期の話で、「評価を変えなくても現場が動く」ことの根拠ではない。

### 5-9 比べ方（チーム独自）

- 比較は**マス目**。横は道筋の進み（まだ動いていない／学習と成長／業務プロセス／顧客／財務）、縦はDXの3段階
- 点は**事業ごとに1つ**。大企業は事業ごとに業種が違うため、同じ業種の事業どうしで比べる
- 事業の縦の位置は、その事業の道筋にある試行・実行中のデジタル施策のうち、一番上の段階
- 他社は、マスの濃さと数字（そのマスにいる事業の割合）で出す。個別の点や企業名、順位は出さない
- 読み方：段階が高くても、道筋を右へ進んでいなければ評価されない

## 6. 設計の意図（なぜこうしたか）

| 決めたこと | 理由 |
|---|---|
| 起点は事業の目標。施策はチップ | DXは手段。施策から描かせると、施策の説明書になってしまう |
| 申請書は事業の方向を先に聞く | 先にDX施策を書かせると、施策を正当化する目標が後から付く |
| 利用率・導入率を「準備の指標」と呼ぶ | 否定せずに、その先（業務・顧客・財務）へつなぐ必要を見せる |
| 足りないところを赤で出す | マップを「できている報告」ではなく「次に話し合うことを見つける道具」にする |
| 答え（推奨KPI・評価制度）を出さない | 経産省は企業の失敗に責任を持てない。会社が自分で決める |
| DXの段階を別途申告させない | 企業が選んだ施策のタグを段階表示に変換する。道筋の進みは、段階とは別に指標の動きから出す |
| 段階を単独のゴールにしない | DXは手段。評価するのは、道筋の中でDXが効いたこと |
| 進みは道筋の順番で数える | 施策と関係なく売上が伸びても、それは今回描いた戦略の成果ではない |
| 合意の割合を比べない | 事業部・経営が先に決めてからDXを盛り込む作り方なので、出した時点で合意は済んでいる |
| 順位を出さない | 施策や事業の切り方が会社ごとに違い、順位は意味を持たない |
| 評価・報酬を条件にしない | 条件にすると参加の壁が高い。評価との衝突は任意の質問で点検する |

## 7. 研究に基づく部分と、チーム独自の部分

| 研究・公的資料に基づく | チーム独自の設計案 |
|---|---|
| 4つの視点と因果、学習と成長の3つの資本、業務プロセスの4分類、財務の2本柱、価値提案の四類型、時間軸の目安（Kaplan & Norton） | 4視点を左から右に寝かせ、施策をチップにした画面の形 |
| 全社 → 事業部 → 支援部門の整合（Kaplan & Norton『Alignment』） | 道筋の進みの判定、実行の準備 |
| 3段階・7項目（IPA） | 7項目ごとの状況を別途自己申告させず、企業が選ぶ施策のタグから段階を、指標の動きから道筋の進みを出すこと |
| 指標の対象の偏り（IPA『DX動向2026』） | 比較のマス目（道筋の進み × DXの段階） |

『戦略マップ』（2004）の内容は、noteの要約記事で確認したもので、原典は確認していない。

## 8. 発表用モックの範囲と、まだ決めていないこと

モック v4は発表用で、本番運用のプロダクトではない。
- 登録するとすぐ戦略マップに反映される（本番では、経産省が確認してから反映する形を想定）
- 公開の範囲は扱わない
- データは架空の1社と、ダミーの他社データ

まだ決めていないことは、設計書25 v0.4の「11. 未決事項」を参照。主なもの：
- 事業の段階がDXの行に集まりやすい（縦の決め方）
- 「指標が動いた」の線引き
- 『戦略マップ』の原典の確認
- 評価・表彰の見立てを支える事実の整理
