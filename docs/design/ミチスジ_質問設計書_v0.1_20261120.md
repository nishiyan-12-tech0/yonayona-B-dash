# ミチスジ　質問設計書 v0.1

2026-11-20

申請画面の問い（ステップの問い・入力欄の問い・説明）を、どの理論のどこに沿って作ったかを記録する。
画面・API・DBの作りは「システム設計書」、戦略マップと申請の項目の全体は「戦略マップ・申請書 設計書 v0.4」を見る。この文書は、問いの根拠だけを扱う。

---

## 1. この文書の目的と範囲

- 対象：申請画面（経営・事業部・DX推進部のトップが戦略を描く場）の問い。
- 対象外：担当者が戦略マップで入力する進捗（施策の状態・指標の今の値など）。2026-11-19に申請から切り分けた。
- 目的：「なぜこの順番で、この聞き方なのか」を、理論の出典とチームの判断に分けて説明できるようにする。

---

## 2. 使っている理論と役割の分担

一つの理論が申請のすべてを保証しているようには書かない。役割ごとに分けて使っている。

| 役割 | 理論・出典 | ミチスジでの使い方 |
|---|---|---|
| 4つの視点 | BSC（Kaplan & Norton 1992） | 戦略マップの4つの列（学習と成長・業務プロセス・顧客・財務）。財務だけで測らず、4つの視点で目標と指標を置く |
| 視点どうしのつながりと、各視点の中身の型 | 戦略マップ（Kaplan & Norton 2000論文、2004『戦略マップ』） | 列どうしの矢印（因果の仮説）。申請のステップ1〜5の順番と、各ステップで聞く中身（財務の2つの戦略、顧客価値提案の4類型、戦略テーマ、3つの資本） |
| 目標ごとの測り方 | BSC（同上） | 目標ごとに「指標・今（申請時点）・目標値・期限」を置き、施策を付ける。『戦略マップ』図表2-2の「戦略マップ（戦略の可視化）→ BSC（尺度と集中）→ 目標値と実施項目」の流れ |
| 複数事業 | Kaplan & Norton『Alignment』（2006） | 全社の目標 → 事業ごとの戦略、の順にそろえる。マップは1枚、戦略は事業ごと |
| 第2層の問いの点検 | 便益管理／BDN（Peppard, Ward & Daniel 2007） | 第2層（DX推進部が加わる）の問いに抜けがないかを点検する補助。骨格としては使わない（5章） |
| DXの物差し | IPAの3段階・7項目 | 施策に付けるIPA項目。段階はこの項目から自動で決まる |
| チーム独自 | ― | 二層構成、全項目必須、実行の準備、申請時点の状態と出発点（6章） |

### 2-1 BSCと戦略マップの関係

- **4つの視点はBSCが元。** BSC（1992年）が、財務・顧客・社内の業務プロセス・学習と成長（当初は「革新と学習」）の4つで指標を置く仕組みとして出した。
- **戦略マップは、その4視点を受け継いで、①視点どうしを因果でつなぎ、②各視点に書く中身の型を足したもの。** 学習と成長 → 業務プロセス → 顧客 → 財務の順に、目標どうしが因果でつながる（『戦略マップ』図表2-1、1-3）。
- ミチスジでは、**4つの列はBSC由来、列どうしの矢印と各列の中身の型は戦略マップ由来、目標ごとの指標・目標値・施策はBSC由来**。

## 3. ステップごとの問いと根拠

ステップの枠組み（準備／第1層 事業の方向／第2層 実現の方法／DXの段階／確認）は変えていない。問いの言い回しと説明だけを、根拠に沿って整えた。

| ステップ | ステップの問い | 入力欄の問い | 根拠 | チームの判断 |
|---|---|---|---|---|
| 0 会社と事業 | どの事業について、戦略を描きますか？ | 会社全体として、中長期でどんな財務目標を目指しますか？／戦略を描く事業はどれですか？ 全社の売上に占める割合は？ | 図表2-2（ミッション・ビジョン → 戦略。ビジョンは中長期の目標を表す）、『Alignment』（全社 → 事業） | 全社の目標は中期経営計画から書く。会社情報はGビズIDで取る前提で聞かない |
| 1 財務の目標 | この事業で、売上・利益をいつまでにどれだけ伸ばしますか？ | 目標と今とでは、どれだけ差がありますか？／その差を、生産性を上げる分と売上を増やす分で、それぞれどれだけ埋めますか？／この事業の財務の目標と、測る指標は何ですか？ | 図表2-3（財務の視点は生産性戦略と収益増大戦略の2つ）、第2章1（長期と短期のバランス） | 財務の目標の種類は2つ（収益増大・生産性向上）にとどめる（7章） |
| 2 顧客への価値 | どの顧客に、どんな価値で選ばれる事業にしますか？ | 誰に選ばれたいですか？／何で選ばれる事業にしますか？（4つから1つ）／顧客にどんな変化を届けますか？／顧客に起きる変化を、どの指標で測りますか？ | 第2章2（目標とする顧客セグメントを識別する）、図表2-5（価値提案の4類型）、図表2-4（価値の中身の要素と、顧客の共通の成果尺度） | 「すべてを少しずつ」は選ばせない（1つを選ぶ）。技術名を使わずに書く |
| 3 戦略テーマと業務 | その価値を届けるために、どの業務を変えますか？ | 選ばれるために、特に力を入れる業務のまとまり（戦略テーマ）は何ですか？ どのくらいの期間で効きますか？（1〜3個）／そのテーマで、どの業務をどう変えますか？ 誰が主に担当しますか？／事業部の誰が、いつ、ここまでの内容を確認しましたか？ | 第2章2・図表2-8（戦略テーマ＝価値提案に効く限られた重要なプロセスのまとまり）、図表2-6（業務の4つの種類）、図表2-7（効くまでの期間の違い） | テーマは1〜3個。業務の4つの種類は選ぶ欄にしない（7章） |
| 4 必要な力と施策 | 業務を変えるのに、人・データ・体制の何が足りませんか？ それをどの施策で補いますか？ | 変える業務のために、どんな人材・情報・組織の力が必要ですか？ 今どれだけ足りませんか？／足りない力を埋めるために、何をしますか？ それはどの目標のための施策ですか？ | 図表2-9（人的・情報・組織の3つの資本）、第7章（戦略への方向づけ・統合性）、図表7-6（レディネス）、第10章（組織資本の4要素）、BDN（5章） | デジタルの施策にはIPA項目を付ける。施策に「申請時点の状態」を付ける（6章） |
| 5 つながりと検証 | なぜその施策で目標に届くと言えますか？ いつ、何で確かめますか？ | なぜその目標が次の目標につながると言えますか？ いつ、何で確かめますか？ | 図表2-1・第2章（4つの視点の目標は因果関係で結ばれる。戦略は仮説の集まり） | 理由・成り立つ条件・次に確かめること・時期の4つで聞く |
| 6 実行の準備 | 施策を動かす予算・人・権限・データはそろっていますか？ | 施策を動かす予算・工数・権限・データの提供者はそろっていますか？ 検証日は決まっていますか？ | BDN（5章：実現のための変化を、誰がいつ行うかまで決める考え方） | チーム独自。事業部とDX推進部の目標の合意は、申請を一緒に作った時点で済んでいるので別に聞かない。評価・報酬の変更は条件にしない |
| 7 道筋にあるDX | 描いた道筋の中に、どの段階のDXがありますか？（自動） | （入力なし） | IPAの3段階・7項目 | 段階は施策に付けたIPA項目から自動で出す。自己申告はさせない |
| 8 一枚で確認 | 経営・事業部・DX推進部の全員で、この道筋に合意できますか？ | （入力なし） | 『Alignment』（事業と支援部門の優先事項をそろえる） | 全員での読み合わせの場とする |

## 4. 『戦略マップ』から取り込んだ観点

申請の説明（問いの下に常に出る文）に反映した内容。図表番号は『戦略マップ［復刻版］』のもの。

### 4-1 財務：2つの戦略と、長期と短期のバランス（図表2-3、第2章1）
- 財務の成果は、生産性の向上（原価構造の改善・資産の有効利用）と、収益の増大（収益機会の拡張・顧客価値の向上）の2つで上がる。
- 収益の増大は、生産性の向上より価値を生むのに時間がかかる。短期の成果を求められると生産性に偏りやすい。
- → ステップ1「差の埋め方」の説明に反映：「生産性は早く効き、売上を増やす道は時間がかかる。両方を描けているかを見る」。

### 4-2 顧客：価値提案の4類型と、価値の中身（図表2-4、2-5）
- 価値提案の4類型：最低のトータル・コスト／製品リーダーシップ／完全な顧客ソリューション／システム・ロックイン。
- 価値の中身：製品・サービスの属性（価格・品質・入手可能性・品揃え・機能性）、関係性（サービス・パートナーシップ）、イメージ（ブランド）。
- 顧客の共通の成果尺度：顧客満足・顧客維持・顧客獲得・顧客別収益性・市場占有率・顧客支払占有率。
- → ステップ2の「将来の提供価値」と「顧客の成果目標」の説明に反映。

### 4-3 業務：戦略テーマと、効くまでの期間（図表2-6〜2-8）
- 業務プロセスは4つの種類（業務管理・顧客管理・イノベーション・規制と社会）に分かれる。
- 効くまでの期間が違う：業務管理は6〜12か月、顧客管理は12〜24か月、イノベーションは24〜48か月（図表2-7）。
- 戦略テーマは、価値提案に最も効く、限られた数の重要なプロセスのまとまり。
- → ステップ3の戦略テーマの問いと、説明「すぐ効くものだけに偏っていないかを見る」に反映。テーマに付ける期間（短期・中期・長期）も、この考え方に合わせている。

### 4-4 学習と成長：3つの資本、戦略への方向づけ、統合性（図表2-9、第7〜10章）
- 3つの資本：人的資本（スキル・知識・価値観）、情報資本（システム・データベース・ネットワーク）、組織資本（文化・リーダーシップ・戦略への方向づけ・チームワーク）。
- 人材やITは、戦略と特定の業務プロセスに結びついて初めて価値が出る（第7章「戦略への方向づけ」）。
- IT投資は、人材の育成や報酬の仕組みと組み合わせないと価値が出ない（第7章「統合性」）。
- 求められる水準と今の水準の差を「レディネス」として見る（図表7-6、第8章）。
- 組織資本の「戦略への方向づけ」は、個人・チーム・部門の目標やインセンティブを戦略目標と結びつけること（第10章）。
- → ステップ4の説明に反映：「組織の力には、文化・リーダー・目標のそろえ方（事業部とDX推進部の目標を戦略に結びつける）・協働の4つがある」「人材とITは、どの業務のためかが決まって初めて価値が出る」「システムを入れる施策には、使う人の育成や役割の見直しもセットで考える」。
- **ミチスジの主張との対応**：チームの主張「事業部とDX推進部の目標が重なる戦略が要る」は、組織資本の「戦略への方向づけ」として、BSCの枠組みの中で問うている。

### 4-5 参考：情報資本の4つの区分（図表9-2）
- 変革アプリケーション／分析アプリケーション／トランザクション処理アプリケーション／ITインフラ。
- 今回は申請の欄にはしていない。IPAの3段階（デジタイゼーション・デジタライゼーション・DX）と考え方が近い部分があるが、対応づけはしていない。

## 5. BDNで点検したこと

便益管理（Peppard, Ward & Daniel 2007）のBDNは、IT投資の目的から、ITの機能までを次の順につなぐ。

投資の目的 → 便益 → 業務の変化 → 実現のための変化（それを可能にする変化）→ IT・ISの機能

ミチスジでは、BDNを骨格にはしない（骨格は戦略マップ）。第2層の問いが、BDNの要素を取りこぼしていないかの点検に使った。

| BDNの要素 | ミチスジで聞いている場所 |
|---|---|
| 投資の目的・便益 | 第1層の財務・顧客の目標（ステップ1・2） |
| 業務の変化 | 変える業務（ステップ3） |
| 実現のための変化 | 必要な力（ステップ4。人的・組織資本） |
| IT・ISの機能 | 必要な力の情報資本と、デジタルの施策（ステップ4） |
| 誰が・いつ実現するか | 主担当（ステップ3・4）、実行の準備（ステップ6） |

点検の結果：目的とITの手段を分けて聞き、その間に「業務の変化」と「実現のための変化」を必ず挟む形になっている。施策（手段）から書き始めないように、第1層（目的）を先に聞く順番にしている。

## 6. チーム独自の判断

既存の理論から直接は導けない、チームの設計判断。

| 判断 | 内容 | 決めた日 |
|---|---|---|
| 二層構成 | 第1層（事業の方向）は経営と事業部、第2層（実現の方法）からDX推進部が加わる。DXを目的にせず、事業の目的を先に決める | 2026-11-15 |
| 全項目必須 | 申請の項目はすべて必須。戦略マップで使わない項目は聞かない | 2026-11-16 |
| 施策は目標に付ける | 施策は列にせず、目標に付けるチップにする（DXは手段なので施策起点にしない） | 2026-11-15 |
| 申請時点の状態と出発点 | 対象はすでにDXを進めている大企業なので、申請で施策の今の状態（検討中・試行中・実行中）を聞き、出し終えた時点の内容を出発点にして、すぐ他社と比べられるようにする | 2026-11-19 |
| 進捗の入力は担当者 | 申請はトップが戦略を描く場。施策の状態の更新や指標の今の値は、担当者が戦略マップで入力する | 2026-11-19 |

## 7. あえて採らなかったことと限界

- **財務の4区分**（原価構造の改善・資産の有効利用・収益機会の拡張・顧客価値の向上）は、今回は選択肢にしていない。今は2つ（収益増大・生産性向上）。発表後の検討事項。
- **業務の4つの種類**は、選ぶ欄にしない（2026-11-16の判断：選ぶ意味が分かりにくい）。効くまでの期間の違いとして、戦略テーマの説明で伝える。
- **原典を確認した範囲**：『戦略マップ［復刻版］』は、手元の写真で第2章（図表2-1〜2-9）、第3章（図表3-1・3-2）、第4章（図表4-6と人的・情報・組織資本の節）、第7章（図表7-1・7-2・7-6）、第8章（図表8-1）、第9章（図表9-1・9-2）、第10章（図表10-1・10-2）、図表1-3を読んだ。それ以外の章は確認していない。
- **有効性は未検証**：この問いで企業が戦略を描けるか、描いた戦略で事業部が動くかは、まだ確かめていない。POC（ビジョンのPhase 1）で確かめる想定。
- **戦略マップの型をDXの成果の実証として扱わない**：4視点の因果は「仮説」として描くもので、矢印があることが効果の証明にはならない。
